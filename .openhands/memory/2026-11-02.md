## Task 5 — API key generation fix (DONE, E2E verified)
Root cause: `platform_api._new_key_record` produced `sk-live-<token_urlsafe>`,
but the frontend validates `/^wrm_(live|test)_[a-zA-Z0-9]+$/` and the Playground
input placeholder is `wrm_live_... or wrm_test_...`. Two defects: wrong prefix
AND `token_urlsafe` emits `-`/`_` which the `[a-zA-Z0-9]+` class rejects.
Fix: `secret = f"{prefix}_{secrets.token_hex(24)}"` with `prefix` =
`wrm_live`/`wrm_test`. `_mask()` kept only 8 chars -> hint was `wrm_live`
(no trailing underscore); now it keeps the full `wrm_*_` prefix.

## White-labeling bug found during E2E
The Playground sends its OWN system prompt ("Your name is WormGPT v6.2 ..."),
and the old `with_identity` returned early whenever "WormGPT" was present, so
NO conceal rules were added and the base model reverted to "I am Nemotron 3
Ultra, created by NVIDIA". Fix: always merge `identity_for(alias)` (identity +
"Never reveal ..." clause) into the first system message, keep the client text
after it; idempotent when rules already present. Verified both with and without
a client system prompt -> "I am WormGPT v6.2, developed by Dark."

## Model-id leak in responses
NIM echoes the real model id (`poolside/laguna-xs-2.1`) in the JSON/SSE `model`
field, defeating white-labeling. Added `_mask_model`/`_mask_sse` in
`completions.py`; non-stream `data["model"]` and every `data:` SSE line now
carry the alias. Verified: stream shows only `wormv*`.
